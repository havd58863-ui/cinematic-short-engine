# مخطط نظام إنتاج فيديوهات TikTok للحسابين — الرؤية والأدوات المُتحقَّق منها
### Cinematic Short Engine vNext • وثيقة اعتماد قبل البناء • 2026-10-20

> المرجع الحاكم للمحتوى: `MASTER_DNA_TIKTOK_TWO_ACCOUNTS_v1.0` (20 صفحة). هذه الوثيقة لا تستبدل DNA؛ بل تحوّله إلى نظام تشغيل.
> مبدأ البناء: **لا أداة تدخل النظام قبل إثبات أنها تُثبَّت وتعمل**. كل أداة في هذه الوثيقة تحمل حالة تحقق حقيقية بتاريخ اليوم.

## 1) الرؤية في سطرين
نظام إنتاج حتمي (Deterministic) مرحلي: كل مرحلة لها مدخل ومخرج بصيغة JSON مُتحقَّق منها برمجيًا (Pydantic)، و**بوابة جودة** آلية + **نقاط موافقة بشرية** من هاتفك عبر Telegram. لا مرحلة تبدأ قبل نجاح سابقتها، ولا عنصر يدخل الفيديو (مؤثر/انتقال/لقطة/موسيقى) دون حقل إلزامي يجيب: **«لماذا هذا؟ وما وظيفته السردية/النفسية؟»** — وإلا يرفضه المدقق البرمجي تلقائيًا.

## 2) خريطة العمل (11 محطة)
```
[أنت – Telegram: «فيديو جديد»]
   0) اختيار الحساب (زرّان) ← تُقفل هوية الحساب على كامل التشغيلة (قفل Anti-Drift)
   1) الجمع    : إشارات حقيقية من أدوات متخصصة (لا اختراع من نموذج لغة)
   2) التحليل  : تجميع/تشابه دلالي/قياس التشبّع والجِدّة
   3) الانتقاء : محرك درجات عددي + حُكم العقل وفق DNA ──◀ موافقتك على الفكرة
   4) السكريبت : كتابة ثم نقد احتفاظ (حلقة محسّنة بعدد محاولات وحد أدنى) ──◀ موافقتك
   5) الإخراج  : Visual Map/Storyboard + Character/World Bible (للحساب 2) + برومبتات ──◀ موافقتك على الستوري بورد
   6) التوليد  : إطارات مفتاحية (Gemini) ← فيديو متواصل (Reactor) مع فحص محتوى لكل لقطة
   7) الصوت    : أداء صوتي بملف إعدادات لكل حساب + ماستر استوديو + محاذاة كلمات
   8) المونتاج : EDL مبرَّر عنصرًا-عنصرًا ← تنفيذ FFmpeg ← ترجمة احترافية
   9) الجودة   : بوابات آلية (تقنية + DNA + استمرارية + قراءة آلية للنص المنطوق)
  10) التسليم  : معاينة + ماستر 1080×1920 + حزمة نشر (عنوان/وسوم) + أرشفة تجربة للتعلم
```
عند فشل أي بوابة: **تتوقف المرحلة برسالة Telegram تسمّي السبب** — لن يُستخدم بديل رديء بصمت قط (درس النسخة السابقة).

### حقيقة يجب أن تعرفها عن «أدوات الترند»
لا يوجد API رسمي مفتوح لترندات TikTok يمنح إشارة موثوقة مجانًا؛ Creative Center واجهة بحث بشرية في الأساس. نظامنا لذلك **متعدد الإشارات**: اهتمام بحثي (Trends) + أنماط منصات مجاورة + مصادر علمية/إخبارية للحساب 1 + مواسم ومناسبات للحساب 2 + **بيانات أداء قناتك أنت** (الأصدق مع الوقت). «غير المتشبعة» تُقاس عدديًا: طلب صاعد مقابل عرض محتوى قليل وبُعد دلالي عن أفكارنا السابقة.

### 4.1 سياسة البدائل المُعلَنة (قرار مالك: عند تعطل محرك انتقل لغيره — دون صمت)
قاعدة صلبة: البديل يُفعَّل **بضغطة موافقة منك في Telegram** بعد رسالة تشرح ما تعطل وما ستراه مختلفًا — أبدًا بصمت:
- **Gemini TTS متعطل/نفدت الحصة** ← Kokoro المحلي بملف الصوت الأقرب لملف الحساب + نفس سلسلة الماستر والمحاذاة.
- **Reactor متعطل** ← الحساب 1: مخزون سينمائي مرخّص (Pexels) منتقى وفق DNA ومُلوَّن بنفس الهوية؛ الحساب 2: إطارات Gemini المرجعية للشخصية/العالم + حركة كاميرا سينمائية بطيئة داخل FFmpeg (وضع مُخفَّض معلن «نسخة إطارات متحركة») حتى عودة Reactor.
- **Gemini (العقل) متعطل** ← تتوقف مراحل الكتابة/الإخراج برسالة؛ لا بديل لغوي أضعف يُمرَّر بصمت، ويُقترح عليك الانتظار أو تبديل نموذج داخل عائلة Gemini من الإعداد.

### 4.2 سلسلة السكريبت الاحترافية — دون Gemini (قرار مالك)
1. **الكاتب**: نموذج مفتوح الأوزان عبر **Ollama** يقوده ملف مهارة «مخرج سكريبت سينمائي» (Beat Map أولًا: hook←escalation←reveal←landing) مُطعَّم بهياكل DNA لكل حساب، ومخرجه يُفرض بمخطط JSON (Pydantic) + صيغة Fountain للتنظيم البشري.
2. **مصقل الاحتفاظ**: نموذج مفتوح ثانٍ بمهارة «محرر احتفاظ» يقيس ويعيد: قوة أول 3 ثوانٍ، فجوة معلومات مفتوحة بلا حل مبكر، تجديد كل 3–6 ثوانٍ، منعطف أوسط، سطر أخير ملتصق بالذاكرة — بدرجات عددية وحد أدنى لا يُعبَر دونه.
3. **مصقل اللغة والأداء**: **LanguageTool** (خادم OSS يستضاف داخل Docker) لقواعد وأسلوب الإنجليزية + `textstat` لوزن الجمل على الإلقاء + مُدقق أداء خاص بنا يحوّل علامات الترقيم إلى وقفات وتشديدات مقروءة لمحرك الصوت.
مرشحا النماذج (يُحسمان بقياس فعلي على المُشغّل): عائلة Qwen وLlama فئة 8B مكمّمة داخل Actions/CPU، أو نفس النماذج المفتوحة مسرَّعة مجانًا عبر Groq عند إتاحة مفتاح مجاني. Gemini يبقى حصريًا لـ: الصوت TTS + الإطارات المرجعية — بطلبك.

## 6) حُكمي على n8n مقابل البديل
- n8n قوي ومحبوب (صورة Docker رسمية محدّثة اليوم، +274 مليون سحبة)، لكن: ترخيصه **Sustainable Use (مصدر متاح، ليس Open Source بمعنى OSI)**، ويحتاج خادمًا يعمل 24/7 لتلقي Telegram — وأنت هاتف فقط وتشترط «مجاني بالكامل». بلا خادم دائم يموت البوت.
- **القرار الهندسي:** Prefect (مفتوح المصدر فعليًا) = عقل التنظيم داخل كل تشغيلة + GitHub Actions = المُجدوِل والمُشغِّل المجاني (مستودع عام: دقائق غير محدودة على مُشغّلات قياسية 4 أنوية/16GB، حد 6 ساعات للوظيفة — نجزّئ المراحل فلا نصطدم به) + Cloudflare Workers = أذن Telegram الدائمة مجانًا. إن امتلكت خادمًا لاحقًا نضيف n8n كطبقة بصرية فوق نفس المهام دون إعادة بناء.

## 7) «ثبّت كل شيء مرة واحدة» — الترجمة الاحترافية لطلبك
المستودعات لا تحمل برامج مثبّتة؛ الاحتراف هو:
1. **Dockerfile** يثبّت كل شيء بإصدارات مقفلة (Python 3.12 + FFmpeg + خطوط Noto/Serif + الحزم أعلاه).
2. GitHub Actions يبني الصورة مرة وينشرها إلى **GHCR** (سجل حاويات GitHub — مجاني للعام).
3. كل إنتاج لاحق يسحب الصورة الجاهزة: **صفر تثبيت، صفر مفاجآت إصدارات** — بيئة متطابقة في كل تشغيلة وفي أي مكان.

## 8) الأسرار وسرية DNA — قراران لك
1. **المفاتيح** (Gemini/Reactor/Telegram): في GitHub **Secrets** فقط — تضيفها أنت من الهاتف (أرشدك لاحقًا)، لا تُكتب في ملف أبدًا. تدوير مفتاح = تغيير Secret واحد، لا يمسّ الكود.
2. **مفاضلة يجب أن تدركها:** بقاء المستودع **عامًا** يمنحنا حوسبة مجانية غير محدودة، لكنه يجعل الكود علنيًا. وملف DNA مصنّف «CONFIDENTIAL». لذلك: المستودع عام بالكود، لكن **إعدادات DNA والأصول الحساسة تُخزن مشفّرة** (age) ومفتاح فكّها في Secrets — تبقى استراتيجيتك سرية حتى داخل مستودع عام. (بديل: مستودع خاص = 2000 دقيقة مجانية/شهر فقط على الخطة المجانية.)

## 9) حدود صادقة (حتى لا أبيعك وهمًا)
- لا نظام يضمن «احتفاظ 100%»؛ نهندس للاحتفاظ (Hook ≤3s، فجوة معلومات، تجديد كل 3–6s، Payoff مُدقَّق) ثم **نقيس ونصحح أسبوعيًا** كما يفرض DNA (§11/§13).
- بوت Telegram يرسل ملفات ≤50MB عبر خوادم Telegram: المعاينة والماستر المضغوط بذكاء إليك داخل المحادثة، والنسخة الأرشيفية الكاملة برابط Release.
- اختبار Reactor/Kokoro/Gemini «الحي» النهائي يُحسم بمفاتيحك عبر بوابات Smoke في أول تشغيلة تجريبية — قبل أي فيديو حقيقي.
