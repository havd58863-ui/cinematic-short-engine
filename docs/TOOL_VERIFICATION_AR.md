**التاريخ:** 2026-10-20  
**القاعدة:** لا تُعتمد أداة لأنها مشهورة؛ تُعتمد بعد حل اعتمادياتها، تثبيتها في بيئة معزولة، وتشغيل اختبار مناسب لها. ما لم يُختبر حيًا يُسمى صراحة «بوابة قبول لاحقة».

## 1) بيئة الاختبار

- Python الإنتاج المستهدف: **3.12.15** داخل بيئات افتراضية مستقلة لكل مجموعة.
- إدارة الاعتماديات: **uv 0.13.3** وأقفال كاملة في `requirements/locks/`.
- بيئة الفحص المحلية محدودة (2CPU / نحو 2GB RAM) ولا تحتوي Docker؛ لذلك فُصلت نتيجة تثبيت الحزم وتشغيلها عن نتيجة بناء صور Docker، وجعل بناء الصور نفسه اختبار CI إلزاميًا على GitHub.
- لم تُستخدم أي مفاتيح حقيقية في هذا التقرير.

## 3) أخطاء اكتُشفت أثناء التحقق وتم التعامل معها

1. **`fountain==0.1.3` مرفوض**: يُثبّت لكنه ينهار عند الاستيراد على Python 3.12 بسبب Regex قديم يستخدم LOCALE مع نمط نصي. استُبدل بـ **Screenplain 0.12.0**، وتم تحويل عينة Fountain فعليًا.
2. **DeepFilterNet 0.5.6 مؤجل/مرفوض للنواة**: لا توجد عجلة CPython 3.12، والبناء من المصدر يطلب Rust/Cargo ويقيّد NumPy وpackaging بنطاقات قديمة. سلسلة الاستوديو المعتمدة الآن حتمية ومُختبرة: FFmpeg speech filters + Pedalboard + PyLoudnorm، وهو نفس اتجاه أداة `audio_enhance` في OpenMontage.
3. **لا بيئة Python واحدة لكل شيء**: WhisperX يفرض `huggingface-hub<1` بينما Sentence Transformers الحديث يطلب `>=1.3`؛ فُصلت الأقفال والصور: `ml` و`align` و`voice-fallback` منعًا لكسر صامت.
4. **PyTorch كان سيسحب CUDA بلا فائدة**: مُشغلات GitHub بلا GPU. أُصلح بقفل Torch من فهرس CPU الرسمي، فانخفضت بيئة ML من 6.0GB إلى 1.6GB في لقطة الفحص.
5. **فشل تجربة OpenCV الأولى كان نقص مساحة مؤقتة لا فشل أداة**: نُقلت بيئة الاختبار من `/tmp` الصغير وأُعيد التثبيت بنجاح.
6. **PySceneDetect ليس حكمًا وحيدًا على الذوبان الناعم**: التقط القطع الصلب ولم يلتقط Dissolve قصيرًا بالإعدادات الافتراضية؛ لذلك ستكون حقيقة المشاهد من EDL الذي نصنعه ومن فحوص إطاراتنا، وPySceneDetect مساندًا بعد معايرة.

## 4) ماذا يعني «مثبّت في المستودع» هنا عمليًا؟

- `requirements/locks/*.txt`: كل نسخة مباشرة وانتقالية مقفلة حسب مجموعة العمل.
- `docker/Dockerfile`: صورة Python واحدة القالب تُبنى لكل مجموعة بقفل مختلف، فتُثبّت في CI مرة وتُسحب جاهزة من GHCR في الإنتاج.
- `vendor/openmontage.lock.json`: OpenMontage عند Commit واحد محدد؛ `scripts/fetch_openmontage.py` يجلبه ويتحقق من HEAD، دون دمج 161MB داخل تاريخ Git ودون انجراف صامت لنسخة أحدث.
- `docker-compose.yml`: Ollama وLanguageTool وn8n كخدمات اختيارية بصور مثبّتة بالـdigest، ولا تعمل إلا بملفات تعريفها حتى لا تلتهم الموارد بلا حاجة.
- `.github/workflows/verify.yml` و`build-images.yml`: بعد الدفع، يثبت CI البيئات ويبني الصور ويشغّل smoke داخل كل صورة؛ لن تُعتبر مرحلة البناء مقبولة إذا بقيت أي وظيفة حمراء.

## 5) بوابات قبول لا تزال مطلوبة قبل أول فيديو حقيقي

1. نجاح Workflow التحقق وبناء كل الصور على GitHub.
2. اختيار نموذج الكتابة المفتوح بقياس أعمى على مشغّل Actions نفسه: جودة إنجليزية، طاعة JSON، التزام DNA، سرعة، وذروة RAM؛ النموذج الصغير الذي نجح محليًا ممنوع للإنتاج.
3. بوابة Gemini الحية بمفتاح المالك: أي نموذج TTS يجيب، عينات أصوات للاختيار، وقفل ملفي الأداء لكل حساب.
4. بوابة Reactor الحية: جلسة قصيرة وإطارات حقيقية غير أحادية ومعاينة قبل أي إنتاج بطوله الكامل.
5. اختبار WhisperX/ffmpeg داخل صورته، وتشغيل عينة Kokoro داخل صورة espeak-ng، وتصيير Remotion بمتصفح داخل صورته.
6. مراجعة قانونية قصيرة لشروط Remotion وAGPL بحسب كيان التشغيل قبل أي استعمال شبكي أو تجاري موسّع.
