# Cinematic Short Engine — نظام إخراج وإنتاج TikTok مفتوح المصدر

نظام إنتاج قابل لإعادة الاستخدام والاستكمال من Google Colab مع حفظ الملفات في Google Drive، ويستهدف جمهور الولايات المتحدة باللغة الإنجليزية وصيغة عمودية 9:16.

## الأدوات المحددة لكل مرحلة

| المرحلة | الأداة | الوظيفة |
|---|---|---|
| مدخل التوجهات | TikTok Creative Center | معلومات التوجهات المتاحة رسميًا؛ لا نفترض وجود API مفتوح |
| البحث | DDGS + Trafilatura | اكتشاف المصادر العامة واستخراج النص مع حفظ الرابط والتاريخ |
| إشارة بحث اختيارية | pytrends | اهتمام البحث على Google فقط، وليس أرقام TikTok |
| كتابة السكربت | أداة كتابة موجودة عبر adapter إن تم إعدادها، وإلا Ollama + `qwen2.5:3b-instruct` | سكربت متماسك بخطاف وتصاعد وخاتمة منطقية |
| المخرج والستوريبورد | Ollama + Pydantic | توقيت كل لقطة، البرومبت الإيجابي والسلبي، الزاوية والحركة والضوء والاستمرارية |
| توليد الصور | Diffusers + SDXL Base 1.0 | صورة محددة لكل لقطة؛ نموذج SD 1.5 بديل معلن للذاكرة الأقل |
| اتساق المرجع | IP-Adapter عبر Diffusers | ينشئ النظام ورقة مرجعية للشخصية المتكررة ويخزنها في Drive؛ ويحاول IP-Adapter عند توافق SDXL، وإلا يستخدم اتساق البرومبتات |
| تحريك الصور بالذكاء الاصطناعي | Wan 2.1 I2V فقط عند ≥48GB VRAM و≥100GB مساحة ذاكرة تخزين، أو Stable Video Diffusion XT عند ≥12GB VRAM | مقاطع neural image-to-video حقيقية عند النجاح |
| البديل عند التعذر | FFmpeg | تحريك pan/zoom؛ يسجل دائمًا كـ `ffmpeg_animation` وليس فيديو مولدًا بنموذج عصبي |
| التعليق الصوتي | Kokoro-82M، الصوت `af_heart` | تحويل النص إلى صوت إنجليزي دون رفع تسجيل من المستخدم |
| الترجمة والتوقيت | Whisper | تفريغ الصوت الناتج فعليًا وإنتاج SRT وASS |
| التحرير والفحص | FFmpeg + ffprobe | دمج المشاهد والصوت والترجمة وتصدير MP4 والتحقق التقني |
| صور احتياطية اختيارية | Pixabay أو Pexels | عند إعداد المفتاح، تُسجّل كصور مخزونة لا كصور مولدة بالذكاء الاصطناعي |

تُحوَّل إشارات الصوت في الستوريبورد إلى مؤثرات إجرائية متزامنة مع المشاهد (whoosh، impact، tick، alarm، radio static، ambience) باستخدام مصادر FFmpeg المحلية؛ فلا ينزّل النظام تسجيلات غير مرخّصة. الموسيقى الخلفية اختيارية، ويجب أن يكون ملفها مسموح الاستخدام.

## الرفع الأولي إلى مستودع GitHub

إذا لم يتمكن اتصال GitHub في ChatGPT من الوصول إلى مستودع جديد أو خاص، نزّل ملف ZIP وافتح `notebook/bootstrap_repository.ipynb` في Google Colab. أضف إلى Colab Secrets سرًا باسم `GITHUB_TOKEN` باستخدام Fine-grained token خاص بهذا المستودع ويمنح صلاحية **Contents: Read and write**. شغّل دفتر التهيئة وارفع ملف ZIP عندما يطلبه؛ سيرفع ملفات المصدر دون حذف المسارات الأخرى. يُقرأ الرمز من Colab Secrets فقط، ولا يُطبع أو يُحفظ في المشروع. هذه الخطوة لمرة واحدة فقط.

## التشغيل

1. افتح `notebook/run_pipeline.ipynb` في Google Colab.
2. اختر GPU من إعدادات بيئة التشغيل إذا كان متاحًا؛ الفيديو العصبي يعتمد على ذاكرة GPU الفعلية.
3. شغّل جميع الخلايا. سيُركّب Google Drive، ويثبت الاعتماديات مع الحفاظ على نسخة Torch الموجودة في Colab، ويشغّل Ollama ويحمل نموذج الكتابة عند الحاجة.
4. اترك `TOPIC = None` للبحث واختيار فكرة، أو أدخل موضوعًا، أو مرّر سكربتًا مكتوبًا مسبقًا. لاستكمال مهمة، أدخل `RESUME_JOB` بمعرّف المهمة السابقة.
5. ستجد الملفات في `Google Drive/TikTokAIDirector/jobs/JOB_ID/`، بما فيها الفيديو النهائي وتقارير الجودة.

مفاتيح Pixabay/Pexels اختيارية فقط للصور الاحتياطية، ويمكن حفظها في Colab Secrets. لا تضع مفاتيحك داخل ملفات GitHub.

## ملاحظة توافق Kokoro مع Python 3.13

يعتمد تثبيت Colab على التزامين مثبتين من المستودعين الرسميين لـ Kokoro وMisaki لإصلاح بيانات توافق Python 3.13؛ لم أستخدم إصدار PyPI ذي بيانات التوافق القديمة. لم يتم تنزيل النموذج الصوتي فعليًا في بيئة التطوير الحالية، لذلك يجب فحص نجاح تنزيل الأوزان والتوليد داخل جلسة Colab نفسها.

## ما يجب معرفته

لا يوجد ضمان واقعي بصفر أخطاء في كل جلسات Colab. يتضمن النظام فحوصات، وتقارير، واستكمالًا بعد التعطل، ولا يخفي الأخطاء. Wan 14B لا يُحمّل إلا إذا توفرت ذاكرة GPU ومساحة تخزين كبيرة تكفيه؛ إذا لم يتوفر GPU أو نموذج متوافق، فلن يدّعي النظام أن نموذج الفيديو العصبي نجح. وقد تكون النتيجة `partial_success` عند استخدام البدائل أو ظهور تحذيرات. راجع `LICENSES.md` قبل النشر التجاري.
